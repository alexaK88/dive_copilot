# Dive Copilot v0.3 — Persistent Mission Core

This increment moves the V2 mission runtime from purely in-memory state to a durable SQL-backed repository while preserving the existing FastAPI and voice-tool contracts.

## What is persisted

The active mission session now persists:

- selected mission and task completion state;
- confirmed diver position;
- observations;
- observation correction history;
- surface messages and questions;
- surface replies and acknowledgement state;
- structured mission events;
- mission start time used by the simulated dive timer.

A backend process restart therefore restores the active mission instead of silently creating a fresh mission.

## Architecture

```text
FastAPI / Voice tools
        ↓
MissionService
        ↓
MissionRepository
        ↓
SQLAlchemy 2
        ↓
SQLite by default
```

The service layer continues to own domain transitions. SQLAlchemy types do not leak into route handlers or domain models.

## Database

By default the application uses:

```text
data/dive_copilot.db
```

Override this with:

```text
DIVE_COPILOT_DATABASE_URL
```

For example:

```text
sqlite:////absolute/path/dive_copilot.db
```

The repository also accepts another SQLAlchemy database URL, which allows a future move to PostgreSQL without changing `MissionService`.

## Mission sessions

Selecting a new mission creates a new mission session and marks the previous session inactive. The public API continues to expose only the current active mission, while previous session rows remain available in the database for future history/reporting work.

Event IDs and observation/message IDs remain local to a mission session, preserving the existing API semantics.

## Current limitations

This increment deliberately uses SQLAlchemy `create_all()` rather than Alembic migrations. Formal migrations should be added before the schema is treated as stable production infrastructure.

SQLite persistence on a cloud platform also requires durable disk storage. For a multi-instance or production deployment, PostgreSQL should be preferred.
